# Скрипт размещения: установка

Скрипт — **отдельный проект Apps Script**, а не файл внутри таблицы. В OzonBooks уже есть свой `Код.gs`
(приём карточек с парсинга, свои `doGet`/`doPost`), и в одном проекте два скрипта конфликтовали бы.
Отдельный проект открывает таблицу по её адресу (`SPREADSHEET_ID` в начале `Code.gs`) и не трогает её скрипт.

Для тестовой и боевой таблицы — два разных проекта: «Размещение книг (ТЕСТ)» и «Размещение книг (БОЕВАЯ)».

## 1. Лист «Остатки 1С» (для режима «Где книга?»)

Только если его ещё нет в таблице.

1. Таблица → **Файл → Импорт → Загрузить** → файл выгрузки из 1С.
2. «Место импорта»: **Вставить новые листы** → «Импортировать данные».
3. Переименуйте лист в **`Остатки 1С`**.

## 2. Проект

1. Откройте **script.google.com** под своим аккаунтом → **Новый проект**.
2. Вверху нажмите «Проект без названия» → назовите **Размещение книг (ТЕСТ)**.
3. Удалите всё в `Code.gs`, вставьте целиком присланный `Code.gs`, сохраните.
4. Проверьте строку `var SPREADSHEET_ID = '…'` в начале — там адрес нужной таблицы
   (для теста уже вписан).
5. Вверху выберите функцию **`setup`** → **Выполнить**.
   Google спросит разрешения. Если появится «Приложение не проверено» — это ваш собственный скрипт:
   **Дополнительные настройки → Перейти на страницу «Размещение книг»** → Разрешить.
   Разрешение будет «на все таблицы»: так Google называет доступ по адресу, на деле скрипт
   открывает только таблицу из `SPREADSHEET_ID`.
6. В **Журнале выполнения** — новые ключи `Ольга: …` и `Влада: …`. Никуда их не пересылайте:
   каждый вводится в телефон своей сотрудницы (**Меню → Сменить ключ устройства**).

## 3. Публикация

1. **Развернуть → Новое развертывание** → тип «Веб-приложение».
2. «Выполнять как»: **Я**. «У кого есть доступ»: **Все**.
3. **Развернуть** → скопируйте URL (заканчивается на `/exec`) и пришлите — приложение переключится на него.

Обновление кода потом: вставить новый `Code.gs` → **Развернуть → Управление развертываниями →
карандаш → Новая версия → Развернуть**. Адрес не меняется.

## Что скрипт делает и чего не делает

- Пишет только в «Место хранения», «Артикул», «Упаковка», габариты, «Размещено», «Размещено кем»
  существующих строк «Лист1». Новых строк не добавляет — это делает только `Код.gs` таблицы (парсинг).
- Листы «Архив…» (все, чьё название начинается с «Архив») и «Остатки 1С» только читает.
- Артикул создаёт один раз (`ячейка_штрихкод`) и больше не меняет, даже при перемещении.
- Каждый пик сначала пишется в «Журнал размещения»; повторная отправка того же пика пропускается.
- Всё, что не удалось применить, попадает на лист «Ошибки».
